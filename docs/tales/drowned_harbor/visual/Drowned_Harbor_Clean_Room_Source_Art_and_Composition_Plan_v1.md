## Required clean-room method

A later authorized contributor must:

1. receive written functional requirements instead of instructions to reproduce a generated image;
2. begin with a blank human-authored editable source;
3. construct geometry from registered gameplay and board authorities;
4. construct UX states from registered interaction and information-class authorities;
5. create independent thumbnails, geometry, layout, silhouettes, and composition;
6. keep a decision log identifying original choices;
7. record every reference actually consulted;
8. record contributors, tools, versions, plugins, fonts, glyphs, third-party assets, licenses, and assistance features;
9. preserve editable-source history and source SHA-256 values;
10. record exact export settings and export SHA-256 values;
11. maintain source-to-runtime lineage;
12. complete independent similarity review before any later lifecycle advancement.

Unknown facts remain unknown. Metadata may not be reconstructed by guessing, inference, or visual resemblance.

## No-pixel-reuse requirements

Later source work must not:

- trace generated pixels;
- vectorize generated images;
- paint over generated images;
- composite generated images;
- crop, upscale, recolor, or retouch a generated image into a source base;
- extract textures, masks, silhouettes, icons, letters, logos, signs, or decorative fragments;
- reproduce generated text, icons, logos, dates, labels, or marks;
- use a generated image as a hidden layer, alignment overlay, projection map, alpha mask, source texture, or runtime asset.

The 25 external images may inform abstract discussion of functional hierarchy, broad mood, material categories, gameplay-state contrast, public/private separation, broad silhouette categories, board-first composition, semantic emphasis, and presentation intensity. Abstract discussion never makes an external image a source file.

## Similarity review

A later independent reviewer must record:

- geometry and layout independence;
- silhouette independence;
- landmark and object-arrangement differences;
- decorative-detail differences;
- originality of text, icons, logos, signs, and marks;
- palette and material-treatment independence;
- absence of generated artifacts, traced contours, vectorized shapes, extracted textures, and masks;
- source-file layer and history evidence;
- contributor, tool, font, asset, license, source-hash, and export-hash completeness;
- unresolved concerns.

Allowed dispositions are:

- `pass_independent_human_authorship_supported`;
- `revise_similarity_or_lineage_concern`;
- `stop_inconclusive`;
- `reject_prohibited_generated_derivative`.

Only the first disposition may support a later lifecycle review. It does not itself create a candidate, source acceptance, runtime approval, or production approval.

## Required records

### Contributor record

Contributor ID, credited/legal name as appropriate, role, organization, assignment or license basis, work period, source families, exact files, references, AI/tool-assistance disclosure, third-party inputs, attestation, and review history.

### Tool record

Tool ID, product, vendor, exact version, license/account type, local/cloud use, plugins, export components, AI features enabled or disabled, files produced, terms or license evidence, and reviewer.

### Font and glyph record

Family/style, foundry/vendor, source, license and version, desktop/game/embedding/modification/distribution permissions, attribution, internal files, export behavior, fallback plan, and reviewer. No font or glyph is approved by this release.

### Third-party asset record

Asset ID, exact name, creator/vendor, source, acquisition date, license evidence, permitted uses, derivative terms, attribution, redistribution limits, affected files/families, SHA-256, and approval status. Generated-image-derived textures or fragments remain prohibited even if listed.

### Source record

Source asset ID, owner, contributors, blank-source statement, independent-composition statement, tool/version, format, dimensions, color profile, layer/group inventory, references, third-party assets, fonts/glyphs, source SHA-256, dates, similarity disposition, and lifecycle state.

### Export record

Export ID, source ID and SHA-256, tool/version, exact settings, dimensions, format, color profile, alpha, compression, export SHA-256, hypothetical future runtime consumer, information class, authority owner, inclusion/exclusion status, and reviewer.

A missing material record blocks later source acceptance and export advancement.

## Source-to-runtime lineage

```text
registered requirement
  → source family
  → blank editable source
  → contributor/tool/font/asset/license records
  → source SHA-256
  → similarity review
  → export recipe
  → export SHA-256
  → later runtime-consumer authorization
```

Any broken link stops advancement.

## Immediate stop conditions

Stop when generated or generated-derived pixels are requested; source creation, runtime composition, Godot, or implementation is requested; a new legal action or runtime field is required; authority ownership cannot be identified; private information would enter public output; material lineage or hashes are missing; similarity review fails or is inconclusive; a hypothesis is presented as evidence; or an accessibility, privacy, security, production, shipping, legal-clearance, or human-evidence claim is requested.
