# v0.2.0-alpha.2 — Drowned Harbor End-to-End Graybox

Issue #104 authorizes this developer-only internal candidate. It extends the merged alpha.1 native scaffold without registering Drowned Harbor in normal production discovery.

## Governed route

The route has exactly eight stages and seven transitions, in the order fixed by the P0.22 contract: Low Tide arrival, Bellhouse ledger, Lighthouse Council, High Water, Last Light, ending resolution, epilogue attribution, and rematch/title cleanup. The implementation provides placeholder geometry and public text only; it is not content-complete and contains no final art, audio, balance, or public-release behavior.

`BoardState` owns spaces, connectors, reachability, positions, and the atomic tide mutations. The alpha.2 RulesSession authority owns stage legality, the Bellhouse decision, Council resolution, High Water, Last Light, and the ending. The alpha.2 RoleSession authority owns all private projections and private-safe epilogue attribution. The session coordinator owns rematch and terminal cleanup. Director output is a no-op proposal over the exact six-field public aggregate allowlist.

## Privacy and continuity

The exact classes are `public`, `controlled_reveal_private`, `seat_private`, and `faction_private`. Shared history, replay, transcript, mirror, diagnostics, captions, and Director inputs are constructed independently from the RoleSession private view. Private objectives, factions, and ending attribution remain absent from all shared outputs.

Disconnect, surrogate control, reconnect, restore, and replay preserve the stable-seat identity, position, public form, source revision, and named RNG state. Invalid, stale, duplicate, wrong-seat, unavailable, malformed, unsupported, and interrupted work is a state-and-RNG no-op. The eighth consecutive rejection returns a bounded, actionable public diagnostic.

## Isolation and export boundary

The only admission path is the existing explicit developer gate with package version 2. Drowned Harbor is not added to the normal Tale catalog, central provider registry, Tale Library, title/setup navigation, startup, fallback selection, saves, or reports. Lantern House remains the sole normal/default Tale.

The new scenario, package, localization, source, and tests are excluded from ordinary Windows and Linux exports. Actual PCK generation, directory inventory parsing, and closed raw-marker scanning are required evidence; configuration inspection alone is insufficient.

Release Management amendment comment `5159081486` authorizes the inherited alpha.1 scaffold validator and workflow in this release's exact 30-path boundary. The validator remains strict by default for the frozen alpha.1 branch. Later governed branches and `main` use the explicit `--skip-git-boundary` mode, which leaves every substantive package, scenario, localization, provider, source, UID, protected-boundary, export, workflow, documentation, and evidence assertion active.

## Known limitations

The graybox is a deterministic technical route with placeholder presentation. It does not claim content completeness, human comprehension, household playtesting, physical-controller validation, television readability, accessibility compliance, privacy or security certification, fun, pacing, fairness, balance, production readiness, or public-release authorization. Automation is machine evidence; issue #39 remains the authority for human evidence.
