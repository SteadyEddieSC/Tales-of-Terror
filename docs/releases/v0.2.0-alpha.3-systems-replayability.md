## Native system architecture

The Alpha.3 session composes the accepted Alpha.2 eight-stage route rather than replacing it. `RulesSession` owns items, cards, resources, encounters, hazards, rescue state, public ending eligibility, and public ending resolution. `RoleSession` owns stable-seat roles, private objectives, Bellmarked state, Tidebound controlled reveals, continuations, reconnect private projection, and controlled-private ending attribution. The Director receives only the closed public/aggregate allowlist and produces bounded proposals. The developer admission coordinator owns candidate construction, explicit snapshot v2-to-snapshot v3 migration, rollback, rematch, exit, and cleanup.

The target authorities are package version 3, scenario version 3, localization version 3, provider version 3, and snapshot v3. The modes are Cooperative for 1–8 seats, Hidden Betrayer for 3–8 seats, and Outbreak for 2–8 seats. Unsupported lower seat counts deterministically fall back to Cooperative before session start. Hunted and Rival Crews remain deferred.

The governed inventory contains six Living role archetypes; six Living, five Bellmarked, and four Tidebound objective families; 12 items; 12 cards; eight resources; 12 hazards; 19 encounters; four continuation forms; and seven ending families. Assignment and selection use named, isolated deterministic streams. The 126-run matrix covers seeds 3101, 3102, and 3103 twice across every supported mode and seat count, with a maximum of 192 accepted actions per run and an actionable public diagnostic after eight consecutive rejections.

The dedicated offline suite contains 72 substantive fail-closed mutations. The inherited Alpha.2 mutation suite remains unchanged at 54/54.

## Persistence, privacy, and exactly-once behavior

The persisted identity inventory is:

- `council_commitment_id`
- `high_water_transformation_id`
- `role_assignment_id`
- `private_objective_assignment_id`
- `faction_assignment_id`
- `tidebound_conversion_id`
- `continuation_transition_id`
- `director_selection_id`
- `ending_resolution_id`

Processed request and event identities, checkpoints, content state, stable-seat state, named RNG states, and private authorities survive save, restore, reconnect, surrogate control, and replay. Migration validates a complete identity-first snapshot-v2 candidate before adoption. Malformed or unknown authority fails closed without replacing the prior active session or consuming state, content, or RNG.

The exact privacy classes remain `public`, `controlled_reveal_private`, `seat_private`, and `faction_private`. Surrogate-controlled seats receive no private projection. Reconnecting the same stable seat receives the same authorized private projection. Shared output and Director input never contain role IDs, private objective IDs or text, unrevealed Bellmarked mappings, private item markers, private attribution, or desirability data.

## Admission and export boundary

Drowned Harbor remains reachable only through the explicit developer admission gate. It is absent from the normal Tale catalog, central provider registry, Tale Library, title/setup navigation, startup, fallback selection, ordinary saves/reports, and normal discovery. Lantern House remains the sole normal/default Tale.

Both ordinary export presets exclude the Alpha.1, Alpha.2, and Alpha.3 Drowned Harbor scenario/data/runtime/test paths. The dedicated workflow generates actual Windows and Linux PCKs, parses their inventories, and scans raw bytes against a closed private and runtime marker inventory. Portable policy validation independently requires the same exclusion.
