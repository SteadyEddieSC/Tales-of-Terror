## Architecture and behavior

Seven typed native authorities live only under
`game/src/tales/drowned_harbor/`: board, empty rules, bounded Director,
social/privacy skeleton, scoped provider, scaffold session, and developer-only
admission gate. The provider constructs and validates a complete candidate before
the gate commits mutable session authority. No package field selects scripts,
classes, callbacks, expressions, or remote content.

The single scaffold request moves from `scaffold_entry` to
`scaffold_terminal`. Requests have stable identities, are exactly once across
snapshot restoration, and reject stale revisions, wrong authority, wrong stable
seat, malformed input, unsupported intent, duplicates, and unavailable state
without changing authoritative bytes or the named RNG state. Snapshot restore is
identity-first and accepts only the exact supported envelope. Reset, exit,
rematch, and rollback discard Drowned Harbor authority; exit/reset return the
normal default identity `lantern_house_vertical_slice`.

The Drowned Harbor provider is not registered in the central provider registry.
The Tale is absent from the normal catalog, Tale Library, title/setup flows, and
ordinary navigation. Lantern House remains the sole normal/default Tale.

## Export boundary

Both ordinary Godot presets exclude the scenario, all Drowned Harbor package
data, all native scaffold sources, and the focused test tree. The dedicated
validator parses actual Godot 4 PCK inventories and scans both export logs and
PCK bytes for the closed scaffold path and identity marker set. Generated
exports and evidence are removed before source-tree cleanliness is checked.

## Scope and limitations

This is an empty structural scaffold. It adds no Low Tide, Bellhouse, Council,
High Water, Last Light, roles, factions, items, hazards, transformations,
endings, balance, final presentation, or authored production gameplay. The
placeholder strings are original internal validation text, not final narrative.
The design-only authoring reference and development-only prototype fixtures are
not runtime inputs.

Automated results are machine evidence and are not production readiness or a
human playtest. They make no claim about fun, pacing, fairness, balance,
physical controllers, television readability, accessibility, privacy or
security certification, final assets, or public release. Issue #39 remains the
human-evidence authority, and Issue #7 remains the naming gate.
